Corners Heuristic — BFS All-Pairs Tour

What Q6 Solves

Given a CornersProblem state (position, visitedCornersTuple), estimate the minimum remaining steps Pac-Man needs to visit all unvisited corners. A plain Manhattan distance is too weak — maze walls make actual distances longer.

state = ((x,y), (c1, c2, c3, c4))
where c_i ∈ {True, False}
outstanding = corners where c_i = False
Algorithm Steps
  1. If no corners remaining → return 0
  2. Call cornerMazeDistances() — BFS from each corner to every reachable cell (cached once per problem)
  3. Try every permutation of remaining corners
  4. For each ordering: sum
        dist(position → first_corner)
        + dist(corner₁ → corner₂) + …
  5. Return the minimum total over all orderings
🔍 cornerMazeDistances() — BFS Pre-computation

This helper runs one BFS from each of the 4 corners, recording the true maze distance to every reachable cell. The result is a dict: { corner → { (x,y) → distance } }. It is computed once and cached on the problem object as problem._cornerMazeDistances, so repeated heuristic calls pay zero overhead.

for corner in problem.corners:
  dist = {corner: 0}
  queue = BFS_queue()
  while not queue.isEmpty():
    curr, d = queue.pop()
    for neighbor in valid_moves(curr, walls):
      if neighbor not in dist:
        dist[neighbor] = d + 1; queue.push(...)
✓ Why It's Admissible

Any optimal solution must physically visit all outstanding corners in some order. The cost of that solution is at least the BFS maze distance of the cheapest such ordering. Therefore h(n) ≤ h*(n) always holds — we never overestimate.

✓ Why It's Consistent

The heuristic is the exact optimal tour cost in a relaxed graph (corners only). For a non-corner move, the triangle inequality gives h(s) ≤ 1 + h(s'). For a corner-eating move, visiting that corner first is a valid ordering, so h(s) ≤ 1 + h(s') still holds.

Food Heuristic — Nearest Dot + Prim's MST
Function: foodHeuristic(state, problem) in searchAgents.py
255
nodes expanded
(max 9,000 for 8/8)
What Q7 Solves

Given (pacmanPosition, foodGrid), estimate the minimum maze steps needed to eat every remaining food dot. The key insight: all food dots are nodes; Pac-Man must form a tour that connects them all — this is structurally similar to the Travelling Salesman Problem.

state = (position, foodGrid)
foodList = foodGrid.asList()
h = closestFood + MST(foodList)
Two-Part Heuristic Formula
h(n) = dist(pos → nearest_food) + MST_cost(remaining_food)
  • Part 1: maze distance (BFS) from Pac-Man to the nearest food dot
  • Part 2: Prim's MST cost connecting all remaining food dots using BFS maze distances as edge weights
🌳 Prim's MST Algorithm on Food Dots

The Minimum Spanning Tree (MST) cost is a lower bound on the cost of visiting all food dots, because any path that visits all dots must include edges spanning every dot, and the MST is the cheapest such spanning structure.

start = foodList[0]
min_dist = { food: mazeDistance(start, food) for food in remaining }
while unvisited nodes remain:
  next_node = argmin(min_dist) # cheapest reachable dot
  mst_cost += min_dist[next_node]
  for node in unvisited:
    min_dist[node] = min(min_dist[node], mazeDistance(next_node, node))

Maze distances are computed lazily with BFS and cached in problem.heuristicInfo['dist_cache'] for O(1) re-use across heuristic calls.

✓ Why It's Admissible

Any complete solution path must: (1) reach the nearest dot (at least closest_dist steps), then (2) connect every remaining dot — a task whose cost is at least the MST of those dots. So h(n) ≤ true cost always.

✓ Why It's Consistent

Each step at most decreases h by 1: eating a food reduces the MST by at most the edge weight between that food and the nearest remaining dot. The triangle inequality guarantees h(s) ≤ 1 + h(s') for every transition.

⚡ Design Contrast: Q6 vs Q7
Q6 Corners: At most 4 corners → at most 4! = 24 orderings. We enumerate all permutations to find the exact optimal tour, making the heuristic maximally tight (equals true h* in the relaxed graph).
Q7 Food: Up to dozens of food dots → exact TSP is NP-hard. We use the MST relaxation (polynomial time with Prim's) as a tight lower bound. The MST cost is always ≤ the optimal tour, preserving admissibility.

Team Viva Defense Hub (Key Oral Exam Questions for All Members)

Direct, structured answers for examiners (Mr. Jeewaka Perera). Filter questions by individual team member.

M1 • Q1. Why does DFS use a Stack (LIFO) and why is it not optimal?
DFS explores as deep as possible before backtracking. A LIFO Stack pops the most recently discovered successor, diving deep into one branch. It is not optimal because it returns the first path it stumbles into, which can be very long (e.g. 130 steps on MediumMaze compared to the optimal 68).
M1 • Q5. In CornersProblem, why can't the state just be Pac-Man's (x, y) position?
A simple position `(x, y)` lacks memory of which corners have been visited. Two paths reaching `(1, 1)` are NOT equivalent if one has visited 3 corners and the other has visited 0. Therefore, the state must be a composite tuple: ((x, y), (c1_visited, c2_visited, c3_visited, c4_visited)).
M2 • Q2. Why does BFS use a Queue (FIFO) while DFS uses a Stack?
BFS must explore nodes level-by-level in order of their shallowest depth. A FIFO Queue guarantees that all nodes at depth $d$ are popped and expanded before any node at depth $d+1$, guaranteeing minimal step count when all step costs are equal.
M2 • Q3. Why MUST UCS check the goal condition upon DEQUEUE rather than ENQUEUE?
In UCS, when a goal node is first generated and added to the Priority Queue (enqueued), there might still be an unexpanded path with lower cumulative cost $g(n)$ in the queue. Only when dequeued from the priority queue is the path cost guaranteed to be minimal. Checking on enqueue breaks optimality.
M2 • Q3. When step costs are equal ($c=1$), what is the relationship between BFS and UCS?
When all step costs are equal ($c=1$), path cost equals depth: $g(n) = \text{depth}(n)$. Therefore, UCS behaves identically to BFS, expanding nodes in strictly increasing order of depth and yielding the exact same 68 expanded nodes and path cost on MediumMaze.
M3 • Q4. How does A* Search balance backward and forward costs?
A* evaluates frontier nodes by $f(n) = g(n) + h(n)$, where $g(n)$ is the exact backward cost accumulated from the start, and $h(n)$ is the forward heuristic estimate to the goal. When $h(n) = 0$ (the `nullHeuristic`), $f(n) = g(n)$, making A* behave exactly like UCS.
M3 • Q5. Why must the CornersProblem state be immutable and hashable in Python?
Graph search algorithms track visited states in Python `set` or `dict` structures for $O(1)$ lookups. Python sets require objects to be hashable. If visited corners were stored in a mutable Python `list`, Python throws `TypeError: unhashable type: 'list'`. Hence, we use an immutable tuple of booleans.
M4 • Q6. What is the difference between an Admissible and a Consistent heuristic, and why does Graph Search require Consistency?
An Admissible heuristic never overestimates the true minimal cost to the goal: $h(n) \le h^*(n)$. While admissibility guarantees optimality in Tree Search, Graph Search requires Consistency (monotonicity): $h(A) \le c(A, B) + h(B)$ (the triangle inequality). Consistency guarantees that when a node is dequeued from the frontier, its accumulated path cost $g(n)$ is already strictly optimal. This eliminates the need to ever reopen or re-expand nodes already in the closed set.
M4 • Q6. How does cornersHeuristic work step-by-step?
1. Extract remaining unvisited corners from state tuple ((x,y), (c1, c2, c3, c4)) where $c_i = \text{False}$.
2. If 0 corners remain, return 0 (goal reached).
3. Query cornerMazeDistances() for pre-computed BFS maze distances from Pac-Man to corners and between corners.
4. Permute all remaining unvisited corners (at most $4! = 24$ permutations).
5. For each ordering, compute total travel cost: $\text{dist}(\text{pos} \to c_1) + \sum \text{dist}(c_i, c_{i+1})$.
6. Return the minimum cost among all permutations. This yields the exact cost of the optimal tour over remaining corners.
M4 • Q6. Why is cornersHeuristic both Admissible and Consistent?
Admissibility: Any valid solution path that visits all 4 corners must visit remaining corners in some permutation. Since we take the absolute minimum path across all permutations using true BFS maze distances, the true path cost $h^*(n)$ cannot be less than our estimate: $h(n) \le h^*(n)$.
Consistency: For any step $s \to s'$, if no corner is visited, the triangle inequality on maze distance guarantees $h(s) \le 1 + h(s')$. If corner $c$ is visited, selecting $c$ as the first stop in the permutation preserves $h(s) \le 1 + h(s')$. Hence $h$ is monotonic.
M4 • Q7. How does foodHeuristic compute its estimate for all food dots?
State is (position, foodGrid). We decompose the remaining work into a two-part heuristic:
h(n) = mazeDistance(position, nearest_food) + MST_cost(remaining_food)
1. Find the nearest food dot using BFS maze distance.
2. Build a complete graph where each remaining food dot is a vertex, and edge weights are true BFS maze distances.
3. Run Prim's Algorithm to compute the Minimum Spanning Tree (MST) cost.
4. Sum nearest-food distance and MST cost. Distances are cached in problem.heuristicInfo['dist_cache'] to avoid recomputing BFS.
M4 • Q7. Why is Prim's MST used instead of a Greedy path or Farthest-Food?
- Farthest-Food only looks at a single dot and ignores the density of remaining dots, resulting in weak pruning (> 12,000 expansions on trickySearch).
- Finding the exact shortest tour visiting all food dots is the Traveling Salesperson Problem (TSP), which is NP-hard ($O(n!)$) and impossible to run at every A* state evaluation.
- MST Relaxation: Any Hamiltonian path visiting all food dots is a spanning tree. The Minimum Spanning Tree is the cheapest possible spanning structure, guaranteeing $\text{Cost}(\text{MST}) \le \text{Cost}(\text{TSP})$. It runs in $O(|V|^2)$ with Prim's algorithm, maintaining strict admissibility while expanding only 255 nodes (well under the 9,000 limit).
M4 • Q6 & Q7. What are your benchmark results and how does caching prevent timeouts?
Q6 mediumCorners: 189 nodes expanded (threshold: 1,200 for full 8/8, 2,000 for 4/8). Passed with 8/8.
Q7 trickySearch: 255 nodes expanded (threshold: 9,000 for full 8/8, 15,000 for 4/8). Passed with 8/8.
Caching Optimization: Without caching, evaluating BFS distances between food dots repeatedly inside the heuristic causes Python to exceed the autograder's 30-second timeout. We cache pairwise BFS maze distances in problem.heuristicInfo['dist_cache'] and corner distances in problem._cornerMazeDistances, reducing repeated evaluations from $O(|V| \cdot |E|)$ to $O(1)$ dictionary lookups.
