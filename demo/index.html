Team Viva Defense Hub (Key Oral Exam Questions for All Members)

Direct, structured answers for examiners (Mr. Jeewaka Perera). Filter questions by individual team member.

M1 • Q1. Why does DFS use a Stack (LIFO) and why is it not optimal?
DFS explores as deep as possible before backtracking. A LIFO Stack pops the most recently discovered successor, diving deep into one branch. It is not optimal because it returns the first path it stumbles into, which can be very long (e.g. 130 steps on MediumMaze compared to the optimal 68).
M1 • Q5. In CornersProblem, why can't the state just be Pac-Man's (x, y) position?
A simple position `(x, y)` lacks memory of which corners have been visited. Two paths reaching `(1, 1)` are NOT equivalent if one has visited 3 corners and the other has visited 0. Therefore, the state must be a composite tuple: ((x, y), (c1_visited, c2_visited, c3_visited, c4_visited)).
M2 • Q2. Why does BFS use a Queue (FIFO) while DFS uses a Stack?
BFS must explore nodes level-by-level in order of their shallowest depth. A FIFO Queue guarantees that all nodes at depth $d$ are popped and expanded before any node at depth $d+1$, guaranteeing minimal step count when all step costs are equal.
M2 • Q3. Why MUST UCS check the goal condition upon DEQUEUE rather than ENQUEUE?
In UCS, when a goal node is first generated and added to the Priority Queue (enqueued), there might still be an unexpanded path with lower cumulative cost $g(n)$ in the queue. Only when dequeued from the priority queue is the path cost guaranteed to be minimal. Checking on enqueue breaks optimality.
M2 • Q3. When step costs are equal ($c=1$), what is the relationship between BFS and UCS?
When all step costs are equal ($c=1$), path cost equals depth: $g(n) = \text{depth}(n)$. Therefore, UCS behaves identically to BFS, expanding nodes in strictly increasing order of depth and yielding the exact same 68 expanded nodes and path cost on MediumMaze.
M3 • Q4. How does A* Search balance backward and forward costs?
A* evaluates frontier nodes by $f(n) = g(n) + h(n)$, where $g(n)$ is the exact backward cost accumulated from the start, and $h(n)$ is the forward heuristic estimate to the goal. When $h(n) = 0$ (the `nullHeuristic`), $f(n) = g(n)$, making A* behave exactly like UCS.
M3 • Q5. Why must the CornersProblem state be immutable and hashable in Python?
Graph search algorithms track visited states in Python `set` or `dict` structures for $O(1)$ lookups. Python sets require objects to be hashable. If visited corners were stored in a mutable Python `list`, Python throws `TypeError: unhashable type: 'list'`. Hence, we use an immutable tuple of booleans.
M4 • Q6. What is the difference between an Admissible and a Consistent heuristic?
An Admissible heuristic never overestimates the true cost to reach the goal: $h(n) \le h^*(n)$. A Consistent (monotonic) heuristic also satisfies the triangle inequality: $h(A) \le c(A, B) + h(B)$. Consistency guarantees optimality in Graph Search without needing to reopen closed nodes.
M4 • Q6 & Q7. How do you design an admissible heuristic for Corners & Food search?
By solving a relaxed subproblem where maze walls are ignored. For corners, we take the Manhattan distance to the nearest unvisited corner plus the minimum spanning tree (MST) distance between remaining corners. Because removing walls can only decrease distance, it is guaranteed to be admissible ($h \le h^*$).
